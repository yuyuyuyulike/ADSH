# 第二阶段总结（熵减 + 修复，R0–R79）

> 目的是给下一个会话（或下一个接手的人）一份**能直接用的经验**：做了什么、怎么做的、
> 踩过哪些坑、哪些事绝对不能做。逐步的详细账在 [HANDOFF.md](../HANDOFF.md) 的 R 表里，
> 逐模块的体检与收官账在 [ENTROPY-AUDIT.md](ENTROPY-AUDIT.md)。

## 一、做了什么（摘要）

- **目标**：不加新功能，只做等价改写与真实缺陷修复；验收看行为不变量（编译 + 单测 + 真机），不看减了多少行。
- **账**：单测 **368 → 800**（79 个类）；六个模块各收了一遍 —— `ui`、`core/agent`、`core/data`、
  `core/tools`、`runtime/termux`、`core/jobs`；提示词与工具按实测报告修了 4 处；发布 **0.2.0（code 12）**。
- **产出形态**：每一步一个提交（提交信息里写清判据与验收），代码、文档、测试同提交；
  纯函数落到同包的新文件里，调用点只留「取事实 + 一行判断」。

## 二、怎么做的（可复用的四件套）

1. **提纯判定**：挑「判错代价高、输入输出全是字符串与布尔」的地方，把它从 Android/IO 里搬出来
   做成纯函数 + 用例；`File.isFile`、`Os.readlink`、`canonicalPath` 这类读取留在调用点。
2. **搬运等价性**：`python scripts/check-move.py --old <旧> --new <新…>` 做代码行多重集比对，
   **旧侧的差异逐行核**（合格的差异只有被改写的标识符、签名、可见性）。
3. **变异测试**：把生产代码改坏 → 看哪些用例失败。**没响的两种可能必须先分清**：
   死代码（删掉）还是网眼（补一条能区分的用例）。反过来也能用：新织的网要拿变异验它拦得住。
4. **真机口径**：装机启动无 FATAL + crash buffer 空只是底线；能走到的路径就走一遍
   （bootstrap 的两条分支、fence 的四种形态、env 自检、phone 通道、release 包）。

## 三、踩过的坑与解法（按类，都是真踩过的）

### 1) Windows / 工具链

- `gradlew` 只能从 bash 直接跑 wrapper；`cmd.exe /c` 会被当成交互式 cmd、一个任务都不跑。
- `sed` 替换串里的 `&` 表示「整个匹配」——改代码别用 sed，用 Python 脚本。
- 用 TS/Python 写替换脚本时**转义会咬人**：模板串里的反引号与美元花括号、
  Python 多行锚点用三引号而不是换行转义（否则 `+ 引号` 挨着转义符时会少一个引号，
  变异体编译失败，看起来像「变异没响」）。
- `adb shell` 后面**只能给一个参数**：给多个时 adb 用空格重拼、设备侧引号分组全丢
  （`sh -c 'pm list packages'` 会退化成打印用法）。复合命令把整串当一个参数传，或用 `sh -s < 文件`。
- `MANIFEST.properties` 里 `nativeLibraryDir` 的值含等号双写：按等号切分取值会**从中间截断**，
  截出来的假路径会让 shim 报 CANNOT LINK（差点被当成真机 bug 报上去）。
- 全库文件必须 LF（所有按换行做锚点的脚本都依赖它）；清理 import 的脚本曾经把文件写成 CRLF，已修。

### 2) Kotlin / JVM

- **块注释会嵌套**：KDoc 里写正则片段（斜杠星号）会开一个嵌套注释，报错出现在**文件末尾**
  （Unclosed comment）。更阴的是 import 扫描器会因此把整个文件当注释 —— 它报「某 import 没用到」时，
  先确认那份文件真的被解析完了。
- 单测方法名不能含点号与斜杠（JVM 直接拒），用顿号或全角。
- 纯 JVM 单测里 `android.util.Log` 会抛 not mocked：判定要提纯到不依赖 Android 的层，
  日志调用收进 `runCatching`，别让它盖掉真正的行为差异。
- 抽纯函数会**切断 Kotlin 顺着 val 的智能转换**：显式 `checkNotNull` + 注释说明，别用 `!!` 兜。
- 别为凑 `data class` 的形状塞假字段（如 `ClipGet(val unused: Unit = Unit)`）—— 用 `data object`。

### 3) Android / 设备

- app 私有目录不可 exec、模拟存储 noexec、硬链接被 SELinux 拒：这些都走 shim 的 `[fs:]` 提示，
  **别偷偷绕过**（改了就等于把平台事实藏起来，模型会按错的假设干活）。
- termux-exec 必须在**执行脚本的那个进程**里，否则 `env` 这种 shebang 找不到解释器；
  `/bin` 恰好是 `/system/bin` 的软链，所以 `/bin/sh` 能跑只是巧合，`/usr/bin/env` 靠的是改写。
- `script`（util-linux）会覆盖 `PS1`，所以别用它验证「App 给终端设的 PS1」。
- release 包不可调试（`run-as` 被拒）：要拉库 / 进沙箱 / 看私有文件就装 debug 包。

### 4) 扫描器与死代码

- 扫描器的正则要覆盖修饰符组合（漏了 `internal suspend fun` 会把「有调用者的文件」报成孤儿）。
- 「只被测试引用、生产零调用」的函数只有两种身份：**有意的测试缝**（KDoc 必须写明）或**死代码**。
- 「生产走不到的分支」就是死代码：把参数类型收紧（只接受那个分支的类型）比留着分支 + 补用例更好。
- 静态扫描器全绿不等于没有死代码，但它能挡住 90%：**每一步都跑，别攒到最后**。

### 5) 诊断与根因

- **静默失败最贵**。用户报的「DeepSeek 不生成会话标题」查了半天，根因是标题那次小调用
  `max_tokens = 64` 却没关思考，推理把预算吃光导致正文为空；而代码里
  `runCatching { … }.getOrNull()` 把它吞得一点痕迹都没有。关键路径的失败要留痕（抛错或日志）。
- 「别的模型行、这个模型不行」先怀疑**请求参数**，别怀疑模型：直接用真实 API 按生产形状打一发
  （本例：不带思考字段 → finish=length、正文 0 字、推理 214 字；带上 disabled → finish=stop、正文 10 字），
  比通读代码快得多。
- 参考实现（dsh）里「空结果」往往有明确语义（抛 `produced no text`）——对齐它，别自己发明兜底。

## 四、必须做 / 绝对不能做

**必须做**

- 一步一提交，提交信息写清「改了什么 + 判据 + 验收」；文档与代码同提交。
- 改 `fence.c` 之后跑 `scripts/fence-selftest.sh`（host 侧 40 项）。
- 关键判定提纯后**先织网再拆**（先补可测性端口与黄金用例，再动那个大函数）。
- 每一步都跑门禁：`:app:testDebugUnitTest :app:assembleDebug`；发版前再 `:app:assembleRelease`。

**绝对不能做**

- 不能为了「看起来整齐」改数值或格式：提示词基线、间距刻度、系统提示词的格式位都不能顺手动。
- 不能重复写同一份东西：提示词不许重复（有测试盯着）、工具说明只在 `ToolSdk.specs` 写一次、
  同一个值写两遍的地方要收成一个来源。
- 不能动：`targetSdk = 28`、包名 `com.termux`、release 的 R8 两个开关、read-only 也挂围栏这条语义。
- 不能把没验过的写成「已验证」：真机没走到的分支要在提交信息里写清楚「没走到」。
- 不能为了「可测」而包一层：包装层要么删掉，要么把判定真正搬进去（生产走不到的分支就是熵）。

需要 Robolectric / androidTest / 真机脚本才能覆盖的层 —— 那是换手段，不是再切一刀。
